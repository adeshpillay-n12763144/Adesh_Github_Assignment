Architecture Summary
Backend/API: Node.js / Express REST API handling CRUD endpoints for ride requests.

Database: MongoDB / PostgreSQL managing users, rides, and logs collections.

Workflow: Feature branch per Jira story (feature/ADESH-X), merged into main via PRs.

Known Limitations
Real-time driver GPS tracking is planned for Sprint 2 and not included in v1.0.0.

Cancellation is currently restricted strictly to pending rides; refund processing is handled manually.
